# 搜索引擎接入计划（统一版本 v0.2.0）

> @Author: 花海
> @Date: 2026/08/17
> @Description: 框架与脚手架已统一版本管理（当前基线均为 v0.1.0），下个版本（v0.1.0 → v0.2.0，两仓库同步）
> 为框架与脚手架接入 Elasticsearch 搜索引擎的实施计划。
> 覆盖两大检索场景：全文搜索（BM25 / 分词 / 聚合 / 高亮）与向量检索（dense_vector kNN，支撑 RAG）。
> 本计划为方案级文档，落地时按里程碑拆分执行，并以本仓库既有 SPI 扩展范式为准。

## 1. 背景与目标

业务侧需要在微服务脚手架中引入 Elasticsearch（以下简称 ES）作为搜索引擎，检索场景分为两类：

| 场景 | 能力 | 典型用途 |
| ---- | ---- | ---- |
| 全文搜索 | BM25 相关性打分、分词、聚合、高亮 | 商品 / 文章 / 文档的关键词检索 |
| 向量检索 | dense_vector + kNN 相似度 | RAG 知识库召回（复用框架 AI 检索链路） |

目标：

1. 框架侧提供统一搜索引擎 SPI，业务自定义实现无需改动框架代码（延续 S3-1 规范：扩展点必须提供默认实现）；
2. 脚手架侧提供 `search` 组件选项（内存默认 / ES 生产 / 自研），派生项目开箱可选；
3. 全文检索与向量检索互不干扰：全文走新增 SPI，向量走既有 `VectorStoreInterface`。

## 3. 方案设计

### 3.1 总体思路

延续框架三件套范式：**SPI 接口 → InMemory 默认实现（保证脚手架可用、测试不触网）→ 生产实现（ES 官方 client）**。

```
web_infra/search/                      # 全文搜索（新增模块，单一职责）
├── search_engine_interface.py         # SPI：SearchEngineInterface
├── in_memory_search_engine.py         # 默认实现：内存倒排 + 简单分词
└── elasticsearch_search_engine.py     # 生产实现：elasticsearch-py（延迟导入）

web_infra/ai/retrieval/                # 向量检索（复用既有接口）
└── elasticsearch_vector_store.py      # 新实现：VectorStoreInterface（dense_vector + kNN）
```

关键决策：

- 全文搜索与向量检索**分属两套接口**：全文语义（索引 / 查询 DSL / 聚合 / 高亮）与向量语义（相似度 top_k）差异大，合并会造成接口方法空置或语义混乱，违背单一职责；
- ES 生产实现**延迟导入**：`elasticsearch-py` 归属 `es` extra，不安装不影响核心包导入；
- 所有检索操作**显式传租户**：ES 实现按 `tenant_id` 前缀隔离索引或别名（延续多租户规范 §2，禁止跨租户命中）。

### 3.2 全文搜索 SPI（新增）

`SearchEngineInterface` 建议最小方法集（落地时以业务场景校验，避免过度设计）：

- `create_index / delete_index`：索引生命周期管理；
- `index_document / bulk_index`：单条 / 批量写入；
- `delete_document`：按文档 ID 删除；
- `search`：关键词查询，返回命中文档 ID、得分、高亮片段（高亮为可选参数）；
- 全部方法显式携带 `tenant_id`。

默认实现 `InMemorySearchEngine`：

- 内存字典存储文档，简单分词（空白 / 中英文混合切分）构建倒排，BM25 简化打分；
- 保证脚手架派生项目无外部依赖即可运行，单测不触网；
- 支持按租户命名空间隔离，容量上限可配（防内存无限增长，参照 `InMemoryVectorStore`）。

生产实现 `ElasticsearchSearchEngine`：

- 基于官方 `elasticsearch-py`（>=8.x），遵循官方 API 文档接入；
- 索引名带租户前缀，如 `{prefix}_{tenant_id}`；
- 支持自定义分析器（IK 等中文分词）配置入口。

### 3.3 向量检索接入（复用既有接口）

`ElasticsearchVectorStore(VectorStoreInterface)`：

- 索引字段含 `dense_vector`（维度与嵌入模型对齐）+ `vector_id`；
- `search` 走 ES 8 原生 kNN 查询（`knn` 选项或 `knn` query），返回 `VectorHit(id, score, vector)`；
- 租户隔离策略同 3.2（前缀隔离索引）；
- 与 `Retriever` / `EmbeddingProviderInterface` 组装方式与 `InMemoryVectorStore` 一致，注入即用，**不改动 retriever.py**。

### 3.4 数据同步（DB → ES）

搜索引擎的写入通常来源于业务库，需解决"业务事务成功但 ES 写入失败"的一致性问题：

- **增量同步**：复用框架 `mq/outbox` 机制——业务表变更事务内写 outbox 记录，outbox 发布器投递索引事件，ES 索引消费方幂等写入（复用 `IdempotentConsumer`）；ES 写入失败走 Outbox 重试 / 死信，不阻断主流程；
- **全量重建**：提供重建任务（复用 `web_infra/schedule` 定时任务或独立脚本），按租户 / 表分批全量重建索引，先建新索引再原子切换别名（ES reindex + alias 切换）；
- **删除同步**：业务删除同样走 outbox 事件，ES 删除采用软删除标记（`deleted: true`）以兼容查询期间的不一致窗口，或直接物理删除（落地时按业务取舍）。

### 3.5 多租户隔离

- 全文与向量实现均按 `tenant_id` 隔离索引命名空间（前缀 + 租户，如 `{app}_search_{tenant}`）；
- 无租户上下文时使用 `no-tenant` 占位（沿用 `tenant_guard.NO_TENANT`），禁止跨租户命中；
- ES 实现内部强制校验：请求传入的 `tenant_id` 与索引名解析出的租户一致，防止越权。

### 3.6 配置与依赖

框架侧 `pyproject.toml` 新增：

- `[project.optional-dependencies] es = ["elasticsearch>=8.0"]`；
- `[all]` 追加 `es`（全量形态含搜索引擎）。

配置段（框架 `application.default.yml` 默认值 + 业务 `application.yml` 覆盖，遵循"环境变量 > 配置文件"）：

- `app.search.enabled`：开关（默认 false，与缓存 / 存储组件一致）；
- `app.search.type`：`memory`（默认）/ `elasticsearch` / `custom`；
- `app.search.elasticsearch.hosts / username / password / index_prefix / verify_certs`：ES 连接与索引前缀；
- `.env` 对应环境变量（脚手架侧），如 `APP_SEARCH_ELASTICSEARCH_HOSTS`。

### 3.7 脚手架组件登记（scaffold_components.py）

在 `COMPONENTS` 新增 `search` 组件，与 `cache / storage / mq` 同构：

- `off: True`（允许不使用）；
- `default: "memory"`（SPI 默认策略，脚手架自身可用）；
- `options`：`memory`（内存默认）/ `elasticsearch`（生产推荐，extras → `("es",)`）/ `custom`（自研，生成 SPI 骨架）；
- `spi`：`SearchEngineInterface`（custom 骨架生成依据）；
- `config: True`：模板 `application.yml` / `.env.example` 配置段标记块裁剪与 `@@IMPL:search@@` 替换；
- 同步处理：`generate_spi_skeletons` 支持 search 组件、`render_extras` 汇总 `es` extra、派生脚本 `new` / `new-service` 的模板渲染校验用例。

## 7. 风险与决策点

| 项 | 说明 | 建议 |
| ---- | ---- | ---- |
| 中文分词 | ES 全文检索中文需 IK 等分析器，属于部署侧配置，框架不绑定 | 配置入口预留 `analysis` 自定义项，脚手架文档给出 IK 安装指引 |
| kNN 最低版本 | ES 原生 kNN 需 8.x | 依赖锁定 `elasticsearch>=8.0`，docker-compose 用 8.x |
| 数据一致性窗口 | outbox 增量同步存在毫秒级延迟，删除采用软删标记缓冲 | 接受最终一致，索引重建兜底 |
| 索引容量 | 全文 + 向量同一索引会增加存储与内存（HNSW 图） | 全文与向量索引分拆（search 索引 / vector 索引），组件内部区分前缀 |
| custom 自研范围 | 业务自研全文实现需对齐接口契约 | 脚手架生成 SPI 骨架 + 接入指引（参照 payment 的 custom 路径） |
| ES 认证与 TLS | 生产需配置用户名密码 / 证书校验 | 配置项 `verify_certs` 默认 true，测试环境显式关闭 |

## 8. 待评审确认事项

1. `SearchEngineInterface` 方法集是否覆盖业务场景（是否需聚合 / 分页 / 排序参数化）；

3. 数据同步采用 outbox 增量 + 全量重建，是否与业务现状一致；
4. 版本节奏：已统一版本管理（框架与脚手架当前基线 v0.1.0，同版本发布）；本次框架与脚手架同步 bump 至 v0.2.0。
