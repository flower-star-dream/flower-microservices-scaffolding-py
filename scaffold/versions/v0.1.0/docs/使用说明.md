# flower 微服务脚手架 使用说明

> 面向业务开发者：如何安装、配置、启动并扩展本脚手架（Monorepo：gateway + user-service + order-service）。
>
> - 上位框架：[flower-web-infrastructure 使用说明](https://github.com/flower-star-dream/flower-web-infrastructure/blob/main/docs/使用说明.md)
> - 框架常量与错误码完整清单：[常量与错误码](https://github.com/flower-star-dream/flower-web-infrastructure/blob/main/docs/常量与错误码.md)（HTTP 状态码统一引用 `HttpStatusConstant`；业务新增常量/错误码前先查阅，防止冲突或重复定义）
> - 本脚手架默认形态：**微服务**（MySQL 服务分库 + Redis 缓存 + Nacos 注册中心 + RocketMQ 消息队列 + MinIO 对象存储，外部依赖由 docker-compose 提供）

## 1. 服务组成与调用链

| 服务            | 端口 | 说明                                                                   |
| --------------- | ---- | ---------------------------------------------------------------------- |
| `gateway`       | 8000 | API 网关：`/api/{service_key}/{path}` 按路由表经注册中心转发到下游服务  |
| `user-service`  | 8001 | 用户管理（独立库 `flower_user`），Redis 缓存，注册到 Nacos              |
| `order-service` | 8002 | 订单管理（独立库 `flower_order`），创建订单 Feign 调用 user-service，发布订单事件（MQ） |

调用链（演示微服务核心能力）：

```
client → gateway（路由转发，FeignClient + 熔断）
           ├─ /api/users/**  → user-service（服务发现：注册中心 → 负载均衡）
           └─ /api/orders/** → order-service（服务发现：注册中心 → 负载均衡）
                                └─ FeignClient → user-service（创建订单时校验用户）
                                └─ 发布 order.created 事件 → MQ（内存 / 生产 RocketMQ，幂等消费）
```

服务注册：三个服务启动时均将自身实例注册到注册中心（`app.registry.type: nacos`，docker-compose 提供；无 Nacos 可切 `memory`）。

## 2. 安装

建议在仓库根创建虚拟环境：

```bash
python -m venv .venv
.venv\Scripts\activate

# 1) 框架依赖（min-microservice = 核心 + MySQL/SQLite + Redis + Nacos + RocketMQ + MinIO，与 docker-compose 对齐）
pip install "flower-web-infrastructure[min-microservice] @ git+https://github.com/flower-star-dream/flower-web-infrastructure.git"

# 2) 工作区工具链（pytest / pyright；根 pyproject 为工作区容器，不声明业务依赖）
pip install -e ".[dev]"
```

> 本地只跑测试可精简为 `pip install "flower-web-infrastructure[mysql,redis,migrate]"`：测试使用内存注册中心 / MQ / 缓存，不依赖 Nacos / RocketMQ / MinIO。
> 各服务业务包通过 pytest `pythonpath` 配置（根 pyproject）直接可见，无需逐个 `pip install -e`；单独在服务目录运行测试时由该服务 pyproject 的 `pythonpath = ["src"]` 保证可导入。

## 3. 本地外部依赖（docker-compose）

```bash
docker compose up -d          # 一键拉起 MySQL / Redis / Nacos / RocketMQ / MinIO
docker compose ps             # 查看各服务健康状态
```

- **MySQL**：容器首次初始化自动执行 `db/init` 基线 SQL（`init-mysql.sh` 依次执行 ddl/dml），创建 `flower_user` / `flower_order` 两库及 t_user / t_order 表，并预置管理员账号（admin/admin123，生产部署前务必修改或删除）。
- 配置项与 `docker-compose.yml` 对齐（root/root、127.0.0.1 各端口），生产环境由运维提供外部服务，应用通过 `.env` 环境变量接入，不依赖本文件。

## 4. 配置说明

配置优先级：**环境变量 > 仓库根 `.env`（自动加载）> 各服务 `application.yml` > 框架默认 `application.default.yml`**。中间件 / 多租户 / AI 等特殊能力默认关闭，由各服务 `application.yml` 显式启用。

**敏感配置（.env）**：复制 [`.env.example`](../.env.example) 为仓库根 `.env` 并填写（`.env` 已被 `.gitignore` 忽略）。**数据库 / Nacos 连接参数全部经 `${ENV:default}` 占位符外置**，非敏感项缺失时用默认值兜底、密码缺省为空字符串。示例（user-service）：

```yaml
app:
  name: user-service
  cache:
    type: redis                          # memory / redis
    redis:
      host: ${APP_CACHE_REDIS_HOST:127.0.0.1}
      port: ${APP_CACHE_REDIS_PORT:6379}
  db:
    type: mysql
    mysql:
      host: ${APP_DB_MYSQL_HOST:127.0.0.1}
      database: ${APP_DB_USER_MYSQL_DATABASE:flower_user}   # 服务分库：user / order 各自独立
      username: ${APP_DB_MYSQL_USERNAME:root}
      password: ${APP_DB_MYSQL_PASSWORD:}
      use_ssl: false                     # 本地无证书关闭 SSL；生产开启
  registry:
    type: nacos                          # memory / nacos
    nacos:
      server_addresses: ${APP_REGISTRY_NACOS_SERVER:127.0.0.1:8848}
```

关键点：

- **服务分库**：user-service 对应 `flower_user`、order-service 对应 `flower_order`（.env 中 `APP_DB_USER_MYSQL_DATABASE` / `APP_DB_ORDER_MYSQL_DATABASE` 区分）。
- **对外注册 IP**：服务注册到 Nacos 的 IP 复用框架 `NacosRegistration` 分级探测，优先级：`register_ip` > `NACOS_REGISTER_IP` > `POD_IP` > `HOST_IP` > 默认网关 > UDP 本机探测 > 回环地址。其中 `register_ip` 本身经框架 Settings 读取——环境变量 `APP_REGISTRY_NACOS_REGISTER_IP` 优先于 application.yml 配置（遵循"环境变量 > 配置文件"）；`NACOS_REGISTER_IP`/`POD_IP`/`HOST_IP` 为框架兼容变量（`NACOS_REGISTER_IP` 优先级低于 yml `register_ip`，属框架既定设计）。生产容器环境必须显式注入（K8s 注入 POD_IP，或运维注入 HOST_IP/NACOS_REGISTER_IP/APP_REGISTRY_NACOS_REGISTER_IP，或配置 `register_ip`），否则下游服务无法访问本实例。
- **雪花 ID**：多实例部署必须为每个实例配置唯一 `SNOWFLAKE_WORKER_ID`（order-service 订单号生成依赖，见 .env.example）。
- **测试**：各服务 `tests/conftest.py` 将 db 替换为 SQLite 内存库（StaticPool），注册中心/缓存/MQ 用 create_app 默认内存实现，测试不触网、不依赖外部服务。
- 已装配组件通过 `app.state.<name>` 访问（cache / db / storage / mq / registry / ai）。

## 5. 启动与验证

```bash
# 各服务在服务目录启动（配置读取依赖 cwd = 服务目录）
cd services/user-service  && uvicorn user_service.main:app  --host 0.0.0.0 --port 8001   # 终端 A
cd services/order-service && uvicorn order_service.main:app --host 0.0.0.0 --port 8002   # 终端 B
cd services/gateway       && uvicorn gateway.main:app       --host 0.0.0.0 --port 8000   # 终端 C
```

验证（先 `docker compose up -d` + 复制 `.env` + Alembic 迁移）：

```bash
curl http://127.0.0.1:8000/health/live                        # 网关存活探针
curl http://127.0.0.1:8001/v1/users                           # 用户分页
curl -X POST http://127.0.0.1:8002/v1/orders -H "Content-Type: application/json" \
     -d '{"user_id": 1, "amount": "99.50"}'                   # 创建订单（Feign 调 user-service 校验用户）
curl http://127.0.0.1:8000/api/orders?user_id=1               # 网关路由转发到 order-service
curl http://127.0.0.1:8000/api/users/1                        # 网关路由转发到 user-service
```

- 服务注册：Nacos 控制台（http://127.0.0.1:8848/nacos）应看到 `gateway` / `user-service` / `order-service`。
- 每服务均有 `/health/live`（存活，不探测依赖）、`/health/ready`（就绪，依赖连通性）、`/metrics`（Prometheus）、`/docs`（Swagger）。

## 6. 数据库变更管理

- **Alembic 为权威变更管理工具**（规范 §13.1），各服务迁移脚本位于 `services/<service>/alembic/versions/`。**迁移命令统一在仓库根执行**（`-c` 指定服务 ini；`alembic/env.py` 自动加载仓库根 `.env`）：

```bash
# 升级到最新版本（URL 解析：USER_DATABASE_URL / ORDER_DATABASE_URL > DATABASE_URL > alembic.ini）
alembic -c services/user-service/alembic.ini upgrade head
alembic -c services/order-service/alembic.ini upgrade head

# 生成迁移（业务模型已在各服务 alembic/env.py 导入注册到 Base.metadata）
alembic -c services/user-service/alembic.ini revision --autogenerate -m "add_xxx"
alembic -c services/user-service/alembic.ini history       # 迁移历史
alembic -c services/user-service/alembic.ini downgrade -1  # 回滚一个版本
```

- **手工 SQL 参考**（规范 §13.2）：基线 `db/init/`（只随大版本重建，禁止回改；docker-compose 自动执行）、增量 `db/versions/`（`V{版本}-{模块}-{描述}-ddl/dml.sql` 成对，涉及存量数据语义变更必须提供幂等 DML；脚本头统一 `@Author / @Date / @Description`）。
- **初始数据**：`db/init/dml/001-user-init-dml.sql` 预置管理员账号（admin / admin123，bcrypt 哈希），生产部署前必须修改默认密码或删除。

## 7. 示例模块说明（用户 / 订单）

**user-service**（分层：`api/v1/user_controller.py` → `service/user_service.py` → `repository/user_repository.py` → `model/user_model.py`）：
演示统一响应 `Result`/`PageResult`、统一错误码（统一抛出约定 `错误码.to_exception()`，如 `CommonErrorCode.COMMON_NOT_FOUND.to_exception()`）、ORM 会话（`db.orm_session()`）、密码加密（`PasswordEncoder`）、缓存空值防穿透（`set_empty`/`is_empty`）、分页（`PageQuery`）。

**order-service**（在用户模块能力之上，额外演示微服务特性）：

| 能力 | 位置 | 说明 |
| ---- | ---- | ---- |
| 服务间远程调用（FeignClient） | `client/user_client.py` | 注册中心发现 user-service + 轮询负载均衡 + 指数退避重试 + 熔断降级（规范 §7） |
| 熔断降级 | `main.py` `_build_feign` + `application.yml` `app.feign` 段 | 超时/重试/退避/熔断参数收敛于 `application.yml app.feign`（框架 `build_feign_client` 配置驱动装配）；未传 fallback 时采用**框架默认兜底**（统一 503"服务不可用"，code=E5-SYS-002）；业务需自定义降级时传 fallback 参数覆盖 |
| 消息事件发布（MQ） | `mq/order_event_publisher.py` | `Message` 统一结构，`partition_key` 按订单 ID 分区保序 |
| 幂等消费 | `mq/order_event_consumer.py` | `IdempotentConsumer`（bizId+msgId 幂等键，重复消费跳过，规范 §9.2） |
| 服务启动注册/停机注销 | `bootstrap.py` | `router.add_event_handler("startup"/"shutdown")` 注册/注销本服务实例 |

**gateway**（`proxy_router.py`）：`/api/{service_key}/{path:path}` 按路由表（`application.yml` 的 `app.gateway.routes`，缺省回落代码内置 `DEFAULT_ROUTES`）经 FeignClient 转发，透传上游状态码与响应体；未知路由返回 404，熔断降级返回 503。

## 8. 扩展新业务模块 / 新增服务

**扩展已有服务的新业务模块**（以 user-service 新增"地址"模块为例）：

1. `model/` 新增实体模型（继承 `web_infra.Base`），在 `model/__init__.py` 导出；
2. `schema/` 新增请求/响应 DTO；
3. `repository/` 新增仓储（统一走 `db.orm_session()`）；
4. `service/` 新增服务（错误码 / 日志 / 缓存）；
5. `api/v1/` 新增控制器，注册到 `api/v1/__init__.py` 的 `api_router`；
6. `main.py` 无需改动（`api_router` 已统一注册）；编写 Alembic 迁移 + 配套 DDL/DML + 测试。

**新增一个独立服务**（推荐）：`python scripts/new_project.py new-service payment-service`（从 order-service 模板复制并重命名包名/服务名/表名/库名/类名前缀，生成后按输出提示手工调整端口与业务语义，详见 [docs/创建新项目.md](创建新项目.md)）。

> 常量规范：权限点 `AUTH_PERM_` 前缀（规范 §6.6）、缓存 Key `web:{module}:v1:{biz}`（规范 §5.7）、事件 Topic 与业务域对齐（规范 §9），禁止裸字符串。
> 注释规范：文件头统一 `@Author / @Date / @Description`，类定义上方注明类的中文名。

## 9. 测试与质量

```bash
.venv\Scripts\python.exe -m pytest                          # 全部测试（三服务 + CLI 脚本；SQLite 内存库，无需外部服务）
.venv\Scripts\python.exe -m pytest services/order-service/tests -q
.venv\Scripts\python.exe -m pytest --cov=app --cov-fail-under=70   # 覆盖率门禁（可选）
.venv\Scripts\pyright.exe                                   # 静态类型检查（新增代码 0 错误）
```

测试约定：各服务 `tests/conftest.py` 提供 `db`（SQLite 内存库 + StaticPool）、`app`（替换 db 组件）、`client`（ASGI 直连）夹具；网关/订单服务测试用 `httpx.MockTransport` 拦截出网请求（不触网）。多服务同名测试文件（如 `test_application.py`）通过根 pyproject 的 `--import-mode=importlib` 按文件路径导入，避免模块名冲突。

## 10. 部署（Docker / CI）

**Docker**：各服务镜像为**自包含多阶段构建**（与单体脚手架 `FROM 框架基础镜像` 不同：微服务需要 nacos/rocketmq/minio SDK，框架基础镜像仅含 min-monolith extras，故 build 阶段经 git+ 安装框架 `[min-microservice,migrate]` 后仅拷贝 site-packages 到 runtime；安全整改与框架 Dockerfile 一致：非 root + 清理构建期工具）：

```bash
docker build -t flower-microservices-user-service:latest  -f services/user-service/Dockerfile  services/user-service
docker build -t flower-microservices-order-service:latest -f services/order-service/Dockerfile services/order-service
docker build -t flower-microservices-gateway:latest       -f services/gateway/Dockerfile       services/gateway

docker run -d -p 8001:8001 --env-file .env flower-microservices-user-service:latest
docker run -d -p 8002:8002 --env-file .env flower-microservices-order-service:latest
docker run -d -p 8000:8000 --env-file .env flower-microservices-gateway:latest
```

**CI**（`.github/workflows/ci.yml`）：推送 main / 版本 tag `v*` / PR 时执行：

- `test`：pyright 静态检查 + pytest 单元测试（框架依赖采用"检出框架仓库 + editable 安装"方式，见 [CI/CD 文档](CI-CD.md)）；
- `build-image`：三服务矩阵（gateway / user-service / order-service）并行构建镜像 → Trivy 扫描 → `/health/live` 冒烟 → 推送 GHCR（`ghcr.io/<org>/<repo>-<service>`；push `main` 推测试标签 + `latest`，版本 tag 推 SemVer + `latest`，PR 不推送）。

详细说明（触发时机、门禁策略、镜像推送标签规范、本地复现）见 [CI/CD 文档](CI-CD.md)。
